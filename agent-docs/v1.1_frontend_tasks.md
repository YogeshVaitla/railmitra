# 🛠️ Frontend Agent Task Specification: Seat Swap V1.1 Bug Fixes

> **Role**: React Native Logic, State Management, Navigation
> **Context**: We delivered V1, but identified a few critical UX oversights during manual testing. 
> **Key Objective**: Unblock the "Browse First" user flow and provide proper history/storage management.

---

## 🚂 Ticket: RM-SW-060 — Fix "Browse First" Flow
**Priority**: P0 | **Files**: `app/swap.tsx`, `components/swap/RegisterTab.tsx`, `components/swap/BrowseTab.tsx`

### Context
Currently, when a user clicks "Start Swapping Now", they are dropped into the `BrowseTab`. However, browsing requires a `trainNo`. Since the `trainNo` input is hidden inside the `RegisterTab`, a user literally cannot browse available swaps without first registering their own seat. This is a massive UX flaw.

### Tasks
1. Extract the `trainNo` (and optionally `journeyDate`) state input out of the `RegisterTab` form.
2. Add a global "Journey Context" header at the top of `swap.tsx` (above the tabs). If `trainNo` is empty, prompt the user to enter their 5-digit Train Number in this header.
3. The `BrowseTab` should now trigger its `getSwapsForTrain` fetch immediately once this global `trainNo` is provided.
4. Pass the global `trainNo` down to `RegisterTab` so they don't have to enter it twice if they decide to register after browsing.

## 🧹 Ticket: RM-SW-061 — Add "Clear Local Storage" Option
**Priority**: P1 | **Files**: `services/swapStore.ts`, `app/settings.tsx`, `app/swap.tsx`

### Context
Users (and QA) have no way to reset their device state if they get into a weird swap scenario, because data is cached persistently in `AsyncStorage`.

### Tasks
1. Ensure `services/swapStore.ts` exports a robust `clearAllSwapData()` function that removes `DEVICE_ID_KEY`, `SWAPS_KEY`, `EVENTS_KEY`, and `SESSIONS_KEY` from `AsyncStorage`.
2. Add a "Danger Zone -> Clear All App Data" red button in `app/settings.tsx` (or inside `/history` or `MySwapTab` empty state).
3. Wrap it in a `Alert.alert("Are you sure?")` confirmation block.
4. Upon clearing, force a reload or navigate the user back to `/` and trigger `Updates.reloadAsync()` (or similar safe state reset).
